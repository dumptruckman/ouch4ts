# OUCH for JavaScript and TypeScript

Use the checkout's analyzer to report file complexity and function OUCH scores.
OUCH, Overall Upkeep and Change Hassle, adds cognitive complexity to CRAP,
Change Risk Anti-Patterns. Reports include both scores.

## Project writes

Leave the target repository unchanged except for reports, coverage files, caches,
and other artifacts generated by the tool. Analyzer bootstrap may install
dependencies and build output at the analyzer checkout root. If the target
project's dependencies or configuration need changes, stop and recommend the
changes to the user.

## Prepare

1. Inspect the target project's
   [source languages, roots, and generated-code exclusions](references/measurement.md#source-discovery-and-cyclomatic-complexity),
   test scripts, package manager, and runtime requirements. Verify that the
   required runtimes and package-manager executables are available.
2. Check coverage prerequisites for the selected report:

   - For fresh coverage, follow [coverage command selection and prerequisites](references/coverage.md#choose-a-command).
     Select an existing script or installed runner that produces LCOV. Pass
     `--coverage-command` when the default does not fit.
   - For comparisons, apply the per-revision checks in [commit comparisons](references/comparison.md).
   - For existing LCOV, no installed runner or provider is required.

   If prerequisites are missing, stop with exact runtime, dependency, version,
   or configuration recommendations.

3. Resolve this skill's directory to an absolute real path. The analyzer checkout
   root is two directories above `skills/ouch4ts`. Verify that the root contains
   the `ouch4ts` manifest, lockfile, source, and build configuration. A copied skill
   alone cannot run the analyzer. Reuse `dist/cli.js` when the build and declared
   runtime dependencies are present. For missing checkout files, dependencies,
   or a build, follow [analyzer bootstrap](references/bootstrap.md).
4. Run from the target project directory with Node 22 or newer. Keep the project's
   runtime when generating coverage. If that runtime is older, generate coverage
   first, then use a compatible Node with `--use-existing-coverage`.

## Choose the report

- For the effect of a PR on maintenance hassle, read [commit comparisons](references/comparison.md). `--compare <target-ref>` scores the merge base and committed `HEAD`, reusing matching cached reports. Complete setup, cache, and function-matching rules live in that reference.
- For current scores in touched functions, use `--since <target-ref>`. It compares
  the merge base with the working checkout, including staged and unstaged tracked
  edits. Untracked files are excluded. Report this limitation without staging
  files for analysis. Internal deletions can select surviving functions. Deleted
  functions and pure renames have no current function to score. Nested edits can
  select both the nested and enclosing function.
- For current project scores, omit both flags.

Use the PR's actual target reference for PR requests.

```bash
node /absolute/path/to/ouch4ts/dist/cli.js --compare origin/main
node /absolute/path/to/ouch4ts/dist/cli.js --since origin/main
node /absolute/path/to/ouch4ts/dist/cli.js --coverage-command 'npm run test:cov -- --runInBand'
```

Replace `/absolute/path/to/ouch4ts` with the resolved analyzer checkout root.
Use `--help` for source roots, exclusions, LCOV paths, and positional path filters.
Normal analysis requires the coverage command to succeed and update LCOV.
`--use-existing-coverage` trusts an existing report's freshness.

## Interpret the result

Start with the largest file cognitive scores or increases. Report CRAP alongside
the largest function OUCH scores or increases, with locations. Cognitive scores
follow the [whitepaper rules](references/measurement.md#cognitive-complexity),
including nested-function depth and recursion cycles. Use independent function
`CC` and coverage to explain CRAP. OUCH adds the full `Cog`. Full coverage leaves
CRAP at `CC` and OUCH at `CC + Cog`. Calibrate limits against representative code.

For successful comparisons, state whether each distinct commit's report was
reused from cache or regenerated. Use the diagnostics described in
[cache and output](references/comparison.md#cache-and-output).

`N/A` means coverage is indeterminate. Check coverage inclusion, paths, and source
maps before attributing `N/A` to missing tests. LCOV measures executable lines.
Shared lines can share hits, and coverage does not establish useful assertions
or full branch coverage. Use the runner's detailed report to investigate
unexpected scores. See [measurement conventions](references/measurement.md).

Normal runs save all function entries and file metrics in `.metrics/ouch.json`.
`--since` shows changed functions and whole-file metrics for files with changed
lines, including module edits outside functions. Path filters narrow both printed
tables. Saved reports retain all analyzed sources. A report request authorizes
analysis. Propose tests or refactoring, and make those changes when requested.
