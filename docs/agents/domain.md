# Domain docs

This repository uses a single-context layout.

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If they do not exist, proceed silently. The domain-modeling skill
creates them when terminology or decisions are resolved.

## Layout

- `GLOSSARY.md`: shared domain terminology.
- `docs/adr/`: numbered architecture decision records.

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals, code, and tests.
If a needed term is missing, check existing project usage and note
any unresolved terminology for domain-modeling.

When proposing something that contradicts an ADR, identify the ADR
and explain why its decision should be reconsidered.
