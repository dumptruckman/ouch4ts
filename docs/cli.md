# CLI reference

The CLI analyzes one JavaScript or TypeScript project per invocation:

```text
ouch4ts [options] [path-fragment ...]
```

A built checkout exposes the CLI through `node /absolute/path/to/ouch4ts/dist/cli.js`.
An installed package exposes `ouch4ts` through npm scripts, npm exec, npx, or a
global installation. `--help` and `--version` require no target project setup.

## Options

The CLI accepts these options:

| Option | Meaning | Default |
| --- | --- | --- |
| `--project <directory>` | Project to analyze | Launching directory |
| `--config <file>` | JSON configuration file, relative to the launching directory | `ouch4ts.config.json` at the project root |
| `--no-config` | Skip configuration loading | Disabled |
| `--source-root <path>` | Source directory, repeatable | `src` |
| `--exclude <glob>` | Exclude project-relative paths, repeatable | No additional exclusions |
| `--lcov <path>` | LCOV report path | `coverage/lcov.info` |
| `--coverage-command <cmd>` | Shell command that generates LCOV | `<package-manager> run test:coverage` |
| `--use-existing-coverage` | Skip coverage generation and freshness checks | Disabled |
| `--since <ref>` | Display current scores for changed functions and files | No change filter |
| `--compare <ref>` | Compare merge-base and committed `HEAD` scores | Disabled |
| `--setup-command <cmd>` | Shell command that prepares each comparison checkout | Detected manager's frozen install |
| `--refresh` | Regenerate cached comparison reports | Disabled |
| `--format <table\|json>` | Stdout format | `table` |
| `--output-dir <directory>` | Report and comparison cache directory | `.metrics` |
| `--version` | Package version | No analysis |
| `-h`, `--help` | CLI help | No analysis |

`--project` and `--config` resolve relative to the launching directory. Source
roots, LCOV, exclusions, output storage, and command working directories use the
selected project. Report paths are relative to that project.

Positional path fragments use case-sensitive OR matching. They filter stdout,
without changing source analysis, saved reports, or caches.

These combinations fail before command execution:

- `--compare` with `--since` or `--use-existing-coverage`.
- `--refresh` or `--setup-command` without `--compare`.
- `--coverage-command` with `--use-existing-coverage`.
- `--config` with `--no-config`.

## Configuration

The default configuration file is optional. An explicit `--config` file must
exist and be readable. Config selection does not change the project.

The configuration accepts these optional properties:

```json
{
	"sourceRoots": ["src"],
	"exclude": ["**/generated/**"],
	"lcov": "coverage/lcov.info",
	"coverageCommand": "npm run test:coverage",
	"setupCommand": "npm ci --ignore-scripts",
	"outputDir": ".metrics"
}
```

`sourceRoots` is a nonempty list of nonempty strings. `exclude` is a list of
nonempty strings and can be empty. Other properties are nonempty strings.
Invalid JSON, wrong types, blank values, NUL characters, and unknown keys fail
before commands run. Executable configs and inheritance are unsupported.

Flags override configuration, and configuration overrides built-in defaults.
Repeated `--source-root` and `--exclude` flags replace the corresponding
configured list. Configured paths use the selected project even when the config
file lives elsewhere.

Report mode, Git references, path filters, format, coverage reuse, and refresh are
invocation options. They are not configuration properties. `setupCommand` runs
only in comparison mode. `coverageCommand` is inactive with
`--use-existing-coverage`.

## Source and coverage inputs

The default source root is `src`. Discovery includes `.js`, `.jsx`, `.mjs`,
`.cjs`, `.ts`, `.tsx`, `.mts`, and `.cts`. Tests, TypeScript declarations, and
common build directories are excluded. JavaScript projects need no TypeScript
configuration or dependency. The
[source selection rules](../skills/ouch4ts/references/measurement.md#source-discovery-and-cyclomatic-complexity)
define exclusions and glob matching.

Package-manager detection uses the nearest `package.json` with `packageManager`
metadata or a recognized lockfile. Metadata takes precedence over lockfiles in
the same directory. The search stops at the Git root or filesystem root and
defaults to npm when no hint exists. The
[coverage command rules](../skills/ouch4ts/references/coverage.md#choose-a-command)
cover ambiguous lockfiles and overrides.

Fresh analysis requires the coverage command to succeed and update LCOV. The
analyzer checks freshness using file metadata, then discovers sources. Files
generated by the coverage command therefore participate in analysis.
`--use-existing-coverage` skips command selection and freshness checks but still
requires valid LCOV.

LCOV paths identify original sources, relative to the project or absolute within
the same checkout. Paths to compiled output can leave original-source coverage
unknown. The [coverage prerequisites](../skills/ouch4ts/references/coverage.md)
cover runner settings and source maps.

## Current reports

The default table output has file metrics followed by function scores:

```text
File complexity
===============
File           CC  Cog  Functions
src/orders.ts   2    1          1

OUCH Report
===========
Function  File             CC  Cog   Cov%  CRAP  OUCH
price     src/orders.ts:1   2    1  50.0%   2.5   3.5
```

Current reports have the JSON shape `{ "entries": [...], "files": [...] }`.
Successful analysis atomically replaces `<output-dir>/ouch.json`.

### Function fields

Each function entry contains these fields:

| Field | Meaning |
| --- | --- |
| `name` | Qualified function name |
| `file` | Project-relative source path |
| `line`, `endLine` | Inclusive, 1-based source line range |
| `complexity` | Independent function cyclomatic complexity |
| `cognitive` | Cognitive complexity, including nested functions and callbacks |
| `coverage` | Line coverage percentage, or `null` |
| `crap` | CRAP score, or `null` |
| `ouch` | CRAP plus cognitive complexity, or `null` |

Unknown coverage, CRAP, and OUCH display as `N/A` in tables. Complexity metrics
remain numeric. Reports with unknown coverage warn and still succeed. Function
rows sort by descending OUCH, then file and line. Unknown scores come last.

### File fields

Each file metric contains `file`, `complexity`, `cognitive`, and `functions`.
The last field counts functions with bodies. File metrics remain available when
coverage is unknown and sort by descending cognitive complexity, then path.

File CC uses different syntax rules from function CC. File cognitive complexity
includes module code and counts nested functions once. The
[measurement conventions](../skills/ouch4ts/references/measurement.md)
define both counters and the score formulas.

### Changed-function selection

`--since <ref>` compares the merge base of the reference and `HEAD` with the
current checkout. The diff includes committed changes plus staged and unstaged
tracked edits. Untracked files are excluded. Invalid references and missing merge
bases fail before coverage runs.

A function is selected when its current line range overlaps added or modified
lines. A deletion selects a surviving function when the lines immediately before
and after the deletion both remain inside it. Fully deleted functions and pure
renames produce no function rows. Edited renames use the new path.

Scores measure each complete current function. A nested edit can select both the
nested and enclosing function. File rows contain complete current metrics for
source files with changed lines, including module edits outside functions.
Test-only changes can leave both tables empty. Saved current reports retain all
analyzed sources.

## Comparison reports

`--compare <ref>` scores the merge base and committed `HEAD` in temporary detached
worktrees. Project, source, and LCOV paths must stay inside the Git repository,
including through symlinks. Configuration resolves once from the launching
checkout and applies to both revisions. Local config edits can affect both
measurements. Local source edits are excluded.

The saved report is `<output-dir>/ouch-comparison.json`. It contains `base` and
`head` commit hashes, function comparisons in `entries`, and file comparisons in
`files`. It preserves the ordinary `ouch.json` report. Path filters narrow stdout,
while saved comparisons retain all metric changes.

File rows sort by descending cognitive delta. Function rows sort by descending
OUCH delta. Test-only edits can change scores. Unknown coverage keeps coverage,
CRAP, and OUCH deltas `null`. Added and removed entries have no numeric delta.
The [comparison reference](../skills/ouch4ts/references/comparison.md) defines
fields, cache behavior, and function matching.

## Stdout, stderr, and failures

`--format json` writes one JSON report to stdout with the same selected rows and
ordering as the tables. Saved reports remain complete. Diagnostics, warnings,
cache status, and child-command output go to stderr. Failed runs emit no result
JSON.

Successful reports, help, and version exit `0`. Invalid arguments or
configuration, unavailable inputs, failed commands, invalid LCOV or source
syntax, and output-write failures exit `1`. Scores do not impose CI quality gates.

Failures leave previous final reports on disk. A report on disk can therefore
belong to an earlier run. Successful comparison caches can survive a later
failure. Temporary comparison worktrees are removed after success or failure.
